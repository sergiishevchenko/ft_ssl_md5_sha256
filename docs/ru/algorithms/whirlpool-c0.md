# Таблица `g_whirlpool_c0`

Где в коде: `srcs/whirlpool/whirlpool_tables.c` — массив `g_whirlpool_c0[256]`.  
Где используется: `srcs/whirlpool/whirlpool.c`, функция `wp_round` — `c = g_whirlpool_c0[idx]`.

Спецификация: [whirlpool.pdf](https://www.karljapetre.com/whirlpool/whirlpool.pdf)  
(Barreto–Rijmen, ISO/IEC 10118-3 / NESSIE).

Связанные документы: [whirlpool.md](whirlpool.md), [whirlpool-rc.md](whirlpool-rc.md).

---

## Зачем эта таблица

В раунде Whirlpool над каждым байтом состояния нужно сделать две вещи:

1. **γ (SubBytes)** — заменить байт `x` на `S[x]` (S-box).
2. **θ (MixRows)** — умножить строку из 8 байт на матрицу MDS.

Если делать это «в лоб» на каждом раунде, будет медленно. PDF §7.1 предлагает **T-tables**: для каждого возможного входного байта `x` заранее посчитать вклад `S[x]` во всю строку после MDS и сохранить как одно 64-битное слово.

```text
g_whirlpool_c0[x]  =  T0[x]  =  упакованные 8 байт:

   S[x]·1 ,  S[x]·1 ,  S[x]·4 ,  S[x]·1 ,  S[x]·8 ,  S[x]·5 ,  S[x]·2 ,  S[x]·9
```

В эталонных реализациях есть восемь таблиц `T0…T7`. У нас одна `C0` (= `T0`); таблицы `T1…T7` получаются **поворотом** этого слова в `wp_round`:

```c
c = g_whirlpool_c0[idx];
if (t > 0)
    c = (c >> (t * 8)) | (c << (64 - t * 8));
```

## Откуда берутся исходные данные

Нужны **две** вещи из PDF. Сам PDF **не печатает** готовый массив `C0[256]` в синтаксисе C — он задаёт строительные блоки.

### 1. S-box — §3.2, деталь §6.2, полная таблица = Table 3 в конце PDF

256 байт. Это подстановка γ:

```text
x  →  S[x]
```

Первые 16 значений (их же видно как старшие байты `g_whirlpool_c0[0…15]`):

```text
 индекс x:  00 01 02 03 04 05 06 07 08 09 0a 0b 0c 0d 0e 0f
 S[x]:      18 23 c6 e8 87 b8 01 4f 36 a6 d2 f5 79 6f 91 52
```

Как читать S-box из уже готовой `g_whirlpool_c0` в репозитории: у каждого слова старший байт равен `S[x]`:

```text
g_whirlpool_c0[0] = 0x18186018c07830d8  →  S[0] = 0x18
g_whirlpool_c0[1] = 0x23238c2305af4626  →  S[1] = 0x23
```

### 2. Матрица MDS (MixRows θ) — §3.4

Циркулянтная матрица 8×8 над полем \(GF(2^8)\):

```text
первая строка:  01  01  04  01  08  05  02  09
```

То есть коэффициенты:

```text
mds[8] = { 1, 1, 4, 1, 8, 5, 2, 9 };
```

Поле: многочлен \(x^8 + x^4 + x^3 + x^2 + 1\), в hex это `0x11D`.

## Как считается одно слово `g_whirlpool_c0[x]`

Алгоритм для фиксированного `x` (0…255):

```text
1. sx = S[x]                         // байт после S-box
2. для j = 0…7:
       byte[j] = sx · mds[j]         // умножение в GF(2^8) / 0x11D
3. слово = byte[0]|byte[1]|…|byte[7] // big-endian → uint64_t
```

Псевдокод:

```c
uint8_t  S[256];              // Table 3 из PDF
uint8_t  mds[8] = {1,1,4,1,8,5,2,9};

for (int x = 0; x < 256; x++)
{
    uint64_t word = 0;
    for (int j = 0; j < 8; j++)
        word = (word << 8) | gf_mul(S[x], mds[j]);
    g_whirlpool_c0[x] = word;
}
```

Весь массив из 256 слов — просто этот цикл по всем `x`.

## Умножение в \(GF(2^8)\)

Сложение в поле = XOR.  
Умножение на 2 (`xtime`):

```text
результат = (a << 1) & 0xff
если у a был старший бит (a & 0x80) ≠ 0:
    результат ^= 0x1d
```

Почему `0x1d`: многочлен `0x11D` = `1 0001 1101`. После сдвига бит \(x^8\) заменяется на \(x^4+x^3+x^2+1\) = младший байт `0x1d`.

Дальше через удвоения:

```text
·1 = само значение
·2 = xtime(a)
·4 = xtime(xtime(a))
·8 = xtime(xtime(xtime(a)))
·5 = ·4 ⊕ ·1
·9 = ·8 ⊕ ·1
```

## Пример 1: `g_whirlpool_c0[0]` (без редукции по краю)

```text
x  = 0
S[0] = 0x18
```

Считаем каждый байт:

| j | множитель | как считаем | байт |
|---|---|---|---|
| 0 | ·1 | `18` | `18` |
| 1 | ·1 | `18` | `18` |
| 2 | ·4 | `18·2=30`, `30·2=60` | `60` |
| 3 | ·1 | `18` | `18` |
| 4 | ·8 | `18·2=30`, `30·2=60`, `60·2=c0` | `c0` |
| 5 | ·5 | `·4 ⊕ ·1` = `60 ⊕ 18` = `78` | `78` |
| 6 | ·2 | `18·2=30` | `30` |
| 7 | ·9 | `·8 ⊕ ·1` = `c0 ⊕ 18` = `d8` | `d8` |

Склеиваем:

```text
18 18 60 18 c0 78 30 d8
→ 0x18186018c07830d8ULL
```

Это первое значение в `whirlpool_tables.c`. Совпадает.

## Пример 2: `g_whirlpool_c0[1]` (здесь нужна редукция)

```text
x  = 1
S[1] = 0x23
```

Удвоения:

```text
xtime(23) = 46          // 0x23 << 1, старший бит был 0
xtime(46) = 8c          // 0x46 << 1, старший бит был 0
xtime(8c) = 05          // 0x8c << 1 = 0x118 → младшие 8 бит 0x18, плюс редукция:
                        //   был бит 7 → ^= 0x1d → 0x18 ^ 0x1d = 0x05
```

| j | множитель | расчёт | байт |
|---|---|---|---|
| 0 | ·1 | `23` | `23` |
| 1 | ·1 | `23` | `23` |
| 2 | ·4 | два xtime → `8c` | `8c` |
| 3 | ·1 | `23` | `23` |
| 4 | ·8 | три xtime → `05` | `05` |
| 5 | ·5 | `8c ⊕ 23` = `af` | `af` |
| 6 | ·2 | `46` | `46` |
| 7 | ·9 | `05 ⊕ 23` = `26` | `26` |

```text
23 23 8c 23 05 af 46 26
→ 0x23238c2305af4626ULL
```

Второе значение в файле. Совпадает.

## Пример 3: `g_whirlpool_c0[0x61]` (байт буквы `a` из сообщения)

В разборе `"abc"` в `wp_round` на `t=0` берётся байт `0x61`:

```text
x      = 0x61
S[0x61] = 0x0f     // из Table 3 / старший байт C0[0x61]
```

| j | множитель | расчёт | байт |
|---|---|---|---|
| 0 | ·1 | `0f` | `0f` |
| 1 | ·1 | `0f` | `0f` |
| 2 | ·4 | `0f·2=1e`, `1e·2=3c` | `3c` |
| 3 | ·1 | `0f` | `0f` |
| 4 | ·8 | `3c·2=78` | `78` |
| 5 | ·5 | `3c ⊕ 0f` = `33` | `33` |
| 6 | ·2 | `1e` | `1e` |
| 7 | ·9 | `78 ⊕ 0f` = `77` | `77` |

```text
0f 0f 3c 0f 78 33 1e 77
→ 0x0f0f3c0f78331e77ULL
```

Именно это значение подставляется в `wp_round`, когда `idx = 0x61`.

## Как это связано с `wp_round`

Для одной выходной строки `row` цикл `t = 0…7`:

```text
idx = байт столбца t из нужной строки состояния (после π)
c   = g_whirlpool_c0[idx]          // вклад γ+θ для столбца 0
если t > 0: повернуть c вправо на t байт   // имитация Tt
result ^= c
```

То есть `g_whirlpool_c0` — это не «магия», а предрасчёт γ и одной строки θ. Поворот даёт остальные столбцы.
